# 研究项目策划

把客户想解决的问题转成值得做、做得成、费用可承受的研究项目。研究设计、执行日历与报价使用同一范围和工作量，发现资源不匹配时回到方案调整。

## 1. 接续材料，确定本次任务

先读委托、已有方案、客户模板、材料和实际进度，明确谁需要在什么时间依据研究决定什么。按用户请求选择工作深度：

| 用户需要 | 本次工作与交付 |
|---|---|
| 完整项目策划 | 需求评估、方法设计、研究框架、执行排期与报价；分别交付计划书、执行方案、对客报价，需要成本核算时另存内部测算 |
| 仅计划书或建议书 | 完成六部分计划书；核对人员、日历和费用可行性，正文汇总，不额外生成详细执行表和报价单 |
| 已有方案，只排期 | 沿用研究设计，从工作包、资源和真实可执行时段开始；交付执行方案，发现设计不可行时提出具体调整 |
| 仅报价 | 核实范围、工作量、占用与计价依据，形成报价及必要内部测算；已有设计足够时直接使用 |
| 修改现有项目 | 依据原约定和实际进度，评估变更对方法、工作量、日期及费用的影响，更新受影响文件 |

一次集中确认会改变方案的缺项：决策用途与读者、对象/地域/时期、必答问题、期限、预算或人力、材料与接触渠道、交付要求。已有答案沿用；次要缺项列为工作假设。完整测试设定可直接用于模拟。

新建方案时读取 [项目类型与交付差异](references/项目类型与交付差异.md)，按主要用途选择设计重点和拟研究成果，可组合行业、企业、用户模块。完整建议书、简版方案加报价、纯执行报价分别确定本次交付深度；只改排期或报价时沿用已有类型和设计。

现有文件注明依据版本，共用研究范围、数量、成果、期限和预算口径，直接在相关文稿中记录。新项目以相对周次或工作日排程，开工日确定后换成实际日期；续作读取已完成产物和已用资源，估计剩余工作。

## 2. 评估需求，形成研究设计

新建或调整研究设计时读取 [研究问题与方法设计](references/研究问题与方法设计.md)。区分业务期望与研究能完成的任务：逐项拆解需求，按决策重要性与求证难度排序，结合资料、渠道和资源说明可完整回答、可部分回答、当前不能回答什么及原因，推荐最能提高决策价值的范围与取舍。

对客标题与正文使用陈述句，不用设问或自问自答。首次出现明确委托方身份、已有业务能力、拟进入业务、市场范围与目标采购群体；委托方和其客户分开称呼。

需求评估先呈现**客户需求理解**，再呈现**研究深度与关键条件**。前者从客户的经营或管理诉求出发，按本项目的需求板块讲清核心问题、具体子问题及需要作出的决定；后者逐块说明本轮能深入回答什么、可提供哪些咨询建议与成果，以及决定回答深度的关键条件与影响。具体资料清单、提供方和落实时间集中放入项目协作或执行安排，不与需求理解混排。条件不足时说明回答范围和调整办法。完整计划书在需求评估章分别展开这两项，翻页HTML先用独立页面说明客户需求理解，再按内容展开研究深度与关键条件；具体方法沿用上述参考。

先盘点证据的对象、时期、口径和覆盖。边界、数据可得性、招募渠道或方法适用性影响设计时，使用当前可用搜索、浏览器、数据库或文件工具做必要预研；打开原文，核对来源与日期，说明发现怎样改变方案。未到位的数据、名单或权限落实到提供方、需要日期和替代办法。预研已能支持设计选择后进入方案。

用连贯文字解释研究思路：依据委托方的业务处境和待作决定，说明需要解决哪些具体问题、为什么选择这些研究办法、预计形成什么回答，以及不同结果怎样影响客户选择或后续研究。按[研究问题与方法设计](references/研究问题与方法设计.md)组织模块关系，检查影响决定的重要问题是否遗漏。对客表达使用公司、产品、人群及市场的具体名称；私下的部门立场转成中立的研究任务。样本和实施细节在方法章展开，汇报节奏在周期章安排。

逐项详述主要方法的适用理由、对象与抽样、关键分组、数量依据、采集内容与指标、实施及材料加工、分析步骤、质量检查和方法衔接。安排反例或能改变判断的观察；多方法证据不一致时，核对人群、场景、时期与测量差异，并安排必要补证。个人资料明确同意、权限和交付匿名化。

完成需求评估、必要预研、总体思路和方法设计后，按 [研究框架设计方法](references/研究框架设计方法.md)搭建本课题的研究板块、具体研究内容、板块关系和拟报告结构；行业与用户研究分别采用参考中的适用方法。框架是本计划书的一部分，沿用前文输入，不重复编写目标、边界或另出证据地图。已有框架可直接修订；仅调整框架的请求也在本 Skill 内完成，先核对已有研究设计。新增分析工作同步反映到方法、任务、日历和费用。

按 [研究项目计划书交付模板](references/研究项目计划书交付模板.md)组织六部分：**客户需求分析拆解与评估、总体研究思路、研究方法详述、研究框架与最终报告结构、团队介绍与分工、研究周期安排**。研究框架章具体展示研究哪些内容及最终成果的组织方式。团队按实际能力和投入配置，人员未定时写岗位与能力要求。验收对应问题覆盖、方法执行和成果可用性。

## 3. 从方法与成果拆到工作任务

沿研究问题安排资料获取、工具准备、招募与授权、预试修订、正式采集、整理质检、分析整合、写作复核及约定修改。每项工作有负责人、明确产出和验收人；粒度以可估算、可分配和可验收为准。

工作包使用 `任务｜目标｜前置输入/任务｜负责人及协作方｜数量与耗时依据｜开始—完成｜产出及接收方｜验收条件/检查人｜风险与备选`。例如交接“有效样本库、剔除记录及变量说明”，同时注明位置与版本。合格材料可按明确批次进入分析。

将公开资料来源/时间/口径检查、问卷和访谈材料验收、分析复算与最终文件检查排到任务中，明确检查者、节点和返工处理。相关审核 Skill 可用时调用，未安装时完成相应检查。客户确认、受访者可约性、付费采购授权及数据版本也是排程依赖。

## 4. 同时推工时与实际日历

排程时读取 [排程与调整方法](references/排程与调整方法.md)。先按数量、单项耗时及组织工作估算净工时，再依据人的作息、招募预约、路程、场地设备和前置任务安排实际日期与容量，汇总占用人天和自然周期。

座谈会、拦截问卷、入户、到场体验、在线访谈和在线问卷分别使用参考中的容量规则。把招募准备、预访谈/预试及修订、正式采集、改约替补、补访核实、分析与客户反馈排入日历。类似多环节一线研究可从六至八周估算，再按实际条件校准。

共同使用的人员和设备排在同一张日历；按日、半日或预约时段检查冲突，允许同日可利用空档合并任务。净工时除以8仅是标准工作量，实际占用与自然历时分别核算；等待不自动计为整日人工。预留明确启用条件、投入人员及费用，已有预留不重复增加。

检查决定交付日的依赖链和外部输入，用一次延迟或回收不足情景检验补救资源与完成时间。期限不可行时给出推荐调整：缩范围、改方法、增加可并行资源或分阶段交付，并说明对研究问题的影响。需要独立执行文稿时使用 [研究执行方案交付模板](references/研究执行方案交付模板.md)。

## 5. 核算成本，形成报价

涉及价格时读取 [计价与变更方法](references/计价与变更方法.md)。分清预算上限、内部成本、对客售价和第三方代付，核对币种、税费、计价单位、采购内容和修改轮次。

先按人、按周核清整个服务期的任务占用、因项目安排额外锁定的时间，以及剩余时间能否承接其他收费工作；形成内部人员占用表，再报价。排定的任务人天只是起点，净工时、全周期占用和对客计费数量分别列明；尚不确定的占用做情景比较。具体字段与算法见[计价与变更方法](references/计价与变更方法.md)。

已有适用对客费率时沿用，并检查完整成本与利润；没有成熟费率时，按全周期人员占用、岗位工资及企业负担、年度可计费产能、运营费用分摊、硬成本和执行预留测算完整成本，再按合理利润目标反推总额，最后编成客户需要的人日、工作包或固定总价明细。参数使用企业资料、有来源的参考或明确情景假设，不能用虚增工作量来匹配目标价格。内部测算固定给出完整成本保本价、目标利润报价、拟成交价对应利润及成本不利情景；报价改价、折扣或范围调整后重新计算。

检查供应商费用包含的招募、酬谢、转录、平台、质检和税费，避免重复计算；内部成本、预留、利润和税费分别核对。缺少成本依据的部分待估或做情景测算，不按零处理。先形成完整范围的合理报价，再与客户预算比较；超预算时说明差额，给出缩减范围方案及减少的研究成果，同步方法和排期。

按 [研究报价单交付模板](references/研究报价单交付模板.md)列工作与费用明细、付款节点与金额、双方责任、外采/差旅/样本结算、有效期、包含项及变更规则。商业条款未定时标为建议或待确认，交付可讨论报价；内部工资、成本和利润测算单独保存。

## 6. 处理变更并检查交付

项目变更先识别原约定、已完成及可复用工作、新增或取消任务，重新推算剩余工作、人员日历、交付日期、费用与付款。区分客户新增范围、供应方执行偏差和约定外部事件，按原计价与责任条款处理。改变已约定范围、价格或期限的选择交由项目负责人决定；其他可继续的工作照常推进。更新相关文件并保留前版与差异，实际进度以产物和验收证据填写。

文字成稿后，已安装且可读取 `hehe-report-writing` 时默认调用润色模式，沿用本任务的交付模板；已有合格编辑稿直接承接，只处理新增或变更内容。未安装、无法读取或用户明确跳过时，按本 Skill 的成文要求和检查项自行定稿。由本 Skill 复核研究设计、样本、日期、费用、商业条件及附件引用；编辑不改变已确认方案。原稿保留，复核后的修改稿按项目命名加“定稿”，后续呈现使用该稿。

完整计划书默认交付同版 Markdown 定稿与16:9翻页HTML，按 [HTML计划书交付规范](references/HTML计划书交付规范.md)选择制作路径：已安装且可用 `hehe-report-presentation` 时默认交给它制作，未安装或不可用时使用随包模板及生成器。呈现 Skill 可用且用户尚未指定形式时，主动介绍16:9、9:16、A4翻页HTML、带侧栏的下拉HTML及可编辑PPT，说明默认16:9；无其他选择即完成默认版，已有要求直接沿用。分页所需内容可由已安装的 `hehe-report-writing` 编排，也可按本 Skill 的逐页设计规则完成；缺少任何一个增强 Skill 都不阻塞计划书交付。

仅排期、报价或局部修改仍交付对应文稿与约定附件，不自动增加整套演示；呈现 Skill 可用且用户未说明时，主动询问是否增加视觉文件，用户选择后制作。Word、Excel、CSV、PDF或演示稿的触发条件、最低内容、保存命名沿用三份交付模板。完整项目的计划书汇总设计与资源，执行方案展开任务日历，报价展开费用及商业条件，避免重复铺写同一内容。

交付前联合核对：计划书的方法设计之后包含研究框架与最终报告结构，具体内容覆盖必答问题、板块层级清楚且由选定方法承接；样本/场次/有效量口径一致；工作包无循环依赖；个人与设备容量可用；人工和现场支出对应日历；价格、税费、付款可复算；正文、附件及版本一致。缺口集中写清提供方、落实时间及影响。删去没有新增事实、推理、执行办法或有用判断的自辩和重复提醒。
