# HTML计划书交付规范

完整计划书默认交付同版Markdown与16:9横向翻页HTML。HTML用于客户演示，Markdown保留可编辑的完整设计；用户明确指定其他载体时遵从。仅排期、报价或局部修改按对应任务交付，不强制重做全套演示。

## 文字定稿与制作路径

先按主 Skill 第6节完成文字润色或自行审校，复核后将Markdown定稿、图表数据、来源、附件及用户已确认的形式交给呈现制作。已有完整计划书使用润色或分页模式，不进入“文本报告独立撰写”重新写方案。

| 可用的增强 Skill | 文字与分页 | HTML制作 |
|---|---|---|
| 两者都没有 | 本 Skill 自行成文、审校及逐页设计 | 使用随包16:9模板和生成器 |
| 只有 `hehe-report-writing` | 默认润色；翻页交付需要时调用其分页模块 | 使用随包16:9模板和生成器 |
| 只有 `hehe-report-presentation` | 本 Skill 自行定稿及逐页设计；已有合格逐页稿直接使用 | 默认由呈现 Skill 制作16:9；选择下拉版时直接接收Markdown，无需分页稿 |
| 两者都有 | 默认润色；翻页交付需要时调用写作 Skill 的分页模块 | 默认由呈现 Skill 制作16:9，或使用用户选择的其他形式 |

呈现 Skill 可用且形式未明确时，主动介绍16:9会议汇报、9:16手机阅读、A4打印批注、带侧栏下拉HTML连续阅读和可编辑PPT，并说明默认16:9。用户未选其他形式时完成默认版；选择PPT时同时保留HTML阅读版。用户明确跳过润色时自行审校，明确取消HTML或指定其他载体时按其要求交付。仅排期、报价或局部修改不自动扩成完整演示。

采用 `hehe-report-presentation` 时，实际读取其主文件，按其图形优先、画布、生成和验收规则制作；本规范中的六章内容、客户表达、独立报价与内容核对要求继续保留。分页报告保留封面、目录、章节引领及封底；下拉报告沿用六章内容，以侧栏目录导航，不强制插入独立章节页。增强路径不再额外生成一份基础HTML。

已安装但无法读取的 Skill 按不可用处理。呈现运行条件不足时先复用可用环境或补齐本次依赖；仍无法运行则使用随包基础路径。基础HTML生成只需Python标准库；没有Python时可将已设计页面填入随包HTML模板。缺少浏览器或PDF依赖不阻塞Markdown及HTML，继续完成已约定格式；确实无法生成的文件在交付清单说明，不显示不存在的PDF下载链接。

## 从研究方案到逐页设计

完整演示包含独立封面、可点击目录、适用时的方案概览、六章正文及独立封底；每章正文前设置独立章节引领页。封面呈现项目名称、委托对象、版本与日期；目录列章名、页码并可跳转；章节引领页以章序、章名、核心问题和本章路径组织，视觉上区别于正文，不重复铺写正文内容。局部节选可省略不适用的结构页。

沿用计划书六部分。概览页作为整份方案的缩影，串起委托方业务目标与研究需求、研究者的需求理解、研究模块及方法、拟交付成果与支持的决定；使用具体产品、人群和市场名称，不能仅展示执行流程。概览与后文重复且不能提供整体理解时可省略，不为凑结构保留空泛页面。研究方法与研究框架充分展开，团队、周期和必要报价随后呈现。每页一个明确主题；标题写具体内容，复杂方法与框架分多页展开。篇幅由内容决定，不限定页数。

需求评估章先设独立的“客户需求理解”页，用客户的业务语言讲清各需求板块的核心问题和决策；随后以“研究深度与关键条件”展开可深入研究的问题、咨询成果及影响回答深度的条件。具体资料、配合要求、责任人和落实时间归入项目协作安排。需求板块按课题划分，内容较多时拆页。

先根据完整稿设计 `章节｜本页要让客户理解什么｜页面标题｜主图形/版式｜关键内容与数字｜完整稿对应位置`，再制作页面。小标签标章节；主标题说明具体对象与分析角度，副标题必填，用完整陈述说明本页故事或方案理由，正文直接展开。三者分工，不重复同一句标题。研究尚未开展时，标题表达方案而非预造研究结论。

| 内容关系 | 适用表达 |
|---|---|
| 研究问题、方法与成果的承接 | 流程图、上下层结构图，连接线说明实际关系 |
| 研究框架与子问题 | 总览架构＋模块展开页；区分研究内容、方法与预期成果 |
| 方法组合与样本配置 | 方法卡、样本矩阵、分层示意，人数与口径直接可读 |
| 执行周期及依赖 | 甘特图、阶段时间轴，表现并行、等待与机动 |
| 方案取舍、资源及交付 | 比较表、责任矩阵、交付示意 |
| 费用等真实数值 | 构成条、对照表；色块与数值对应，面积按数值比例 |

图形承担比较、层级或过程信息；不能把原长段落逐块装进卡片就算完成设计。保留决策依据、方法细节、样本、职责、日期、费用和条件；详细说明放对应展开页或附录，演示与完整稿对应同一方案。内部工资与利润测算单独保存。

## 页面构图与图形组件

先完成正文和页面内容，再选内容关系与构图。背景与需求可以用连贯段落配目标说明；研究思路用关系图配解释；比较用表格。信息卡只用于确实并列的事项，卡片标题也须意思完整。正文通过适当字号、行距和段落宽度支持连续阅读，不把整页做成醒目的大字短句。正文可用主图加侧栏、双轨对照、旅程时间轴、方法泳道、样本矩阵、架构图、甘特图或交付物预览；相邻页面内容不同，构图也应随之变化。每页突出一个主图或主信息区，说明文字围绕它展开，卡片用于并列事项。

封面用课题相关的主题图形建立识别，章节页沿用同一图形语言和大章序；目录保持清楚的阅读顺序。正文用字号、面积和深浅区分主次，避免所有信息等重。表格突出分组、关键列及合计，图表直接标数；颜色和面积承载实际含义。

随包基础模板提供 `evidence-lanes`（材料—加工—成果泳道）、`journey`（阶段旅程）、`mockups`（交付预览），以及原有矩阵、流程与甘特组件。按课题改写节点、关系和说明，图形不能替代方法细节。交付预览展示拟成果的结构和字段，标为“结构示意”，不填虚构研究发现。

完成后先看全稿缩略图，调整连续同构、视觉重点不足、图文失衡的页面，再放大检查图形与正文。封面、目录、章节及不同正文版式均需实际渲染。

## 面向客户的安排与商务页

周期页说明什么时候做什么、客户何时拿到成果；内部净工时、排班和容量推算保留在执行底稿。协作表按具体日期列“研究方提交材料｜客户/门店需提供或确认｜负责人及反馈时间｜完成标志”，招募名单、预约、门店安排和每周汇报都落实到具体事项。

交付清单独立于报价。报价页列岗位或工作包、数量、对客单价、金额、直接支出及税费，按实际工作量承接总价；篇幅不足拆页。无报价版同时移除其他页面的金额、付款和商务引用，重算目录及页码。封底用项目名称和下一步沟通事项收束；联系人未知不编造。

标题、说明和强调行都写客户能理解的具体内容，少用“输入、闭环、承接、收口”等抽象词。读完后应知道谁在什么时候做什么、交什么，而不必了解研究团队的内部工作术语。

## 随包基础路径：固定视觉

本节及下节用于未采用呈现 Skill 的16:9基础交付；采用呈现 Skill 时使用其模板和生成规则。

使用随包 `assets/proposal-slides.html`，逻辑画布1280×720，等比适配窗口。白底正文、深蓝标题和表头，浅蓝分组；封面采用蓝白体系。1280×720画布可从正文18—20px、行距1.6—1.75、表格17—18px、主标题30—34px开始，副标题略高于正文层级，按实际字体和阅读距离检查；字号不是硬性容纳手段。装不下时先调整图文比例或拆页，保留必要解释。按内容选择布局，保持对齐、留白与字号层级；短语完整换行，避免孤字。

| 用途 | 色值 |
|---|---|
| 封面、标题 | #173F58 |
| 主色、流程 | #245B78 |
| 分组底色 | #DCEAF3 |
| 正文／说明 | #17212B／#667482 |
| 页面／边框 | #FFFFFF／#DCE4EA |
| 少量重点提示 | #A9474A |

颜色表达层级或明确的类别，暗红不用于装饰性编号。图表沿用同一色板，文字与图例可直接阅读。

## 随包基础路径：生成与检查

将已经设计的页面写成UTF-8 JSON，脚本只组装显式页面，不对Markdown自动分页。每页的`body`是本地编写的HTML图形与布局，可用模板内的`grid`、`flow`、`step`、`gantt`、`panel`、表格等组件，必要时内嵌SVG。外部材料先提取事实与文字，不直接作为可执行HTML嵌入。

```json
{
  "title": "项目建议书",
  "footer": "项目名称 · 版本日期",
  "slides": [
    {
      "kind": "content",
      "section": "研究思路",
      "title": "本页的具体研究设计",
      "lead": "解释本页重点的一句话",
      "body": "<div class=\"flow\">本页经设计的内容与图形</div>"
    }
  ]
}
```

页面`kind`可为`cover`（封面）、`toc`（目录）、`chapter`（章节引领）或`content`（正文）。目录页的章目可用`onclick="show(页索引);return false"`跳转，页索引从0开始；正文增删后同步更新目录页码和跳转目标。

使用Python标准库运行：

```text
python scripts/render_proposal.py 页面设计.json 同名计划书.html
```

生成文件离线打开即可翻页，支持目录、左右键、全屏及浏览器打印。脚本检查空页、正文页副标题缺失和重复标题，不覆盖同名文件。页面拆分由内容设计决定；跨页表格保留表头与完整行。模板及组件随本Skill携带，无需其他Skill。

交付前在浏览器查看逐页截图：先检查封面、目录及逐章引领齐全、顺序与跳转正确，再看页面是否清楚表达比较、层级或过程，再检查重复标题、断词、图例、对齐、留白及裁切。方法与框架完整，样本/日期/金额与Markdown相同；导航和离线加载正常，打印一页一张16:9页面。先在不借助聊天记录、口头解说和相邻页的条件下，读出本页对象、主要意思及对客户的用途；读不出时返回文案补齐，再制作。几何无溢出不等于内容或视觉合格。HTML与Markdown保存同目录、同主题与版本；页面设计源文件一并保留便于修改。明确要求可编辑PowerPoint时另生成PPTX，HTML不标作PPTX。

## PDF交付

演示HTML同时提供经过验证的PDF，避免浏览器默认纸张、背景图形和页眉页脚设置改变版式。采用呈现 Skill 时由其导出与所选画布一致的PDF，下拉版按A4自然分页；本节以下为随包16:9路径。随包`export_proposal_pdf.py`使用Playwright及Chromium（可通过`--browser`指定本机兼容浏览器），固定1280×720对应的16:9纸张、零边距、背景色开启、浏览器页眉页脚关闭。导出需要安装Playwright及可用浏览器；HTML本身仍可独立离线阅读。

运行`python scripts/export_proposal_pdf.py 计划书.html 计划书.pdf`，成功导出后自动增加或更新HTML下载入口；导出失败不修改HTML。页面JSON可设置`pdf_file`为同目录已有PDF文件名，仅在文件存在时显示入口；导出到其他文件夹时，脚本按实际位置更新链接。浏览器打印是备用入口，网页CSS的保色和纸张声明不能代替用户打印设置。检查实际PDF页数、16:9尺寸、颜色和边缘内容，无日期、网址等浏览器附加内容；渲染封面、深色章节和表格页检查。计划书自身的项目名及页码保留。
