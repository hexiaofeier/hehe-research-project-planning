# 研究项目计划书交付模板

## 一、交付载体

默认交付同版 Markdown 完整计划书与16:9横向翻页HTML演示计划书，文字定稿与增强 Skill 的选用沿用主 Skill 第6节，按 [HTML计划书交付规范](HTML计划书交付规范.md)选择增强或随包制作路径并检查；用户选择其他形式时按其要求交付。客户已有建议书模板或招标要求时，按其结构组织并覆盖以下核心内容。用户只要求局部修订时，交付相应修改及受影响的范围、方法或资源说明。

## 二、Markdown 主报告

主报告按以下六部分展开。开头可用一段概述推荐方案；客户有固定模板时映射这些内容。表格用于比较，正文讲清研究者的判断与设计理由。

六部分是内容骨架；按 [项目类型与交付差异](项目类型与交付差异.md)调整篇幅及客户所需的呈现顺序，设计各类项目实际要交付的研究成果。简版方案加报价可合并呈现核心设计，纯执行报价沿用已有设计。存在备选方案时，集中比较研究覆盖、方法样本、成果、周期、价格及主要取舍。

1. **客户需求分析、拆解与评估：** 先单列“客户需求理解”，按具体商业诉求划分板块，逐块解释客户要解决的问题与待作出的决定；随后展开可深入研究的问题、可提供的咨询成果及影响研究深度的关键条件。资料索取、责任人和提交时间另列项目协作安排。 客户背景、业务目标、决策用途与读者；将诉求拆为研究问题，明确对象、地域、时期与边界。按重要性和实际求证难度排列，结合材料、接触渠道、人力、预算与期限，评估能完整回答、部分回答和当前不能回答什么及原因。最后提出推荐研究范围、优先顺序和资源取舍，说明本项目能最大化提供的决策价值。关键假设与待落实条件放在对应评估处。
2. **研究方案的总体思路：** 从客户待作的决定说明研究安排：每个模块解决什么具体问题、采用什么方法及选择理由、形成怎样的回答、如何影响客户行动；解释各模块的联系及结果不同后的下一步。按[研究问题与方法设计](研究问题与方法设计.md)展开，表图辅助呈现这条思路，不以方法清单、抽象名词流程或汇报节奏替代。
3. **研究方法设计详述：** 按主要方法分别写对应问题、选用理由、对象与数量依据、采集内容和指标、实施与材料处理、分析步骤、质量检查及方法间的衔接。写出本项目实际怎么做；信息缺失时说明替代设计及成果变化。涉及个人资料时说明同意、权限和匿名化安排。
4. **研究框架与最终报告结构：** 承接前文需求评估、总体思路和方法设计，按 [研究框架设计方法](研究框架设计方法.md)呈现有课题含义的研究板块及下一级内容，说明板块之间的联系与最终报告的组织顺序。每块具体写研究什么、比较什么、将形成怎样的分析成果；需要时注明拟用表图或模型。本章直接展示框架，目标、边界与方法执行安排沿用前文。末尾列明交付载体、附件、使用方式及验收标准，结论留待研究形成。
5. **团队介绍与分工：** 实际成员的相关能力与经历、岗位职责、投入、协作及复核关系，客户的资料与协调责任。人员未定时列拟配置岗位和能力要求；说明如何覆盖方法所需能力及工作量。
6. **研究周期安排：** 阶段起止时间、工作及成果、前置条件、双方责任和完成判据；按具体日期列协作和汇报节点：研究方提交什么材料、客户或门店提供/确认什么、双方负责人、反馈期限及完成标志；开工日未定时用“启动后第几个工作日”，确认后换实际日期。有一线调研时显示招募准备、预试与修订、分批执行、改约替补及补访窗口；客户正文列基准周期、机动窗口、每阶段工作及交付；净工时、逐人占用和每日容量放内部执行方案，用于核实可行性。需要客户协调的到店、邀访与场地安排写清时间和负责人。交付清单与报价分别成页或成节，报价可整体抽走；需要报价时列对客人天单价、数量、金额、直接支出、税费及总价，内部成本另存；说明尚待落实的资源与后续可选工作。

## 三、其他交付物

| 触发条件 | 交付物 | 应包含什么 |
|---|---|---|
| 客户要求正式可编辑文稿 | Word 计划书 | 与 Markdown 同版的正文、表格和附录，核对标题、表格及分页 |
| 客户明确要求可编辑PowerPoint | PPTX演示文件 | 与计划书同版的设计、资源和交付内容；核对分页及实际呈现，HTML不替代PPTX |
| 工作量、情景预算或排期复杂且需要调整 | Excel 工作底表 | 工作包、数量、工时或费率依据、公式及汇总；数值与正文一致 |
| 预研资料或需求条目较多 | 主报告内的材料/需求附录 | 来源、日期、可用内容、对应问题；客户必答条目对应正文位置 |

附件用于具体协作需求，不因格式齐全而额外生成。详细执行方案、正式报价及研究工具另有任务时再制作。

## 四、保存与命名

保存到用户指定位置；已有项目沿用其计划目录，否则在当前工作目录建立该研究项目的计划目录。采用 `YYYYMMDD_研究主题_研究项目计划书_v1.md/.html`，附件保持同一主题和版本；用户有命名规范时遵从。修改已有文件时保留原稿，复核后的修改稿加“定稿”，HTML及其他视觉文件使用该稿；本轮新生成的润色前稿放在 `过程稿/`，已有原稿沿用原位置。交付清单写明定稿与对应视觉文件的实际路径。

## 五、信息缺口

重大缺项先集中询问；能够提出可讨论方案时，标明工作假设及其对设计的影响。区分“用户待确定的选择”和“研究团队需要核实的事实”，分别给出决策或核实时间。可选工作与基础交付分开。

## 六、交付条件与交付前检查

计划书至少应让读者理解研究为什么值得做、怎样做成、能拿到什么。对照检查：

- 客户目标已拆解并评估难度、可回答程度与资源取舍，推荐范围有理由。
- 研究思路说明每项研究解决的客户问题、选择理由及决策用途，模块关系连贯；影响决定的行业、对象或经营条件没有因模板遗漏。
- 样本选择和数量有依据，主要分组能支撑计划中的分析。
- 人力、期限、招募、数据权限与费用相容；自然周期包含预约等待、预试修订、改约补访和反馈时间，预留工作有人员与费用承接；待落实条件有具体安排。
- 研究框架置于方法设计之后，板块内容具体、层级清楚且覆盖必答问题；报告结构与框架合为一套，所需分析有选定方法承接；团队能力和分工覆盖方法，周期安排体现前置依赖。
- 验收检查对应研究任务，不预设研究必须得出某种结论。
- 预研事实能追溯，未核实的前提标为假设；正文和附件版本、数值一致。
- 客户正文用业务对象和具体动作写标题、说明与配合事项；如“会员购买和到店记录”“门店联系人”“确认访谈时间”。必要专业词首次出现时解释；内部排人工时及自检话术留在工作底稿。
- 首次阅读者能够判断推荐理由与关键取舍；删除重复免责和只为避免质疑的文字。
- 完整翻页HTML含独立封面、可点击目录、每章引领页及封底；目录页码与跳转对应实际章节。选择下拉HTML时，目录对应实际章节与小节，正文连续阅读。
- HTML按所选形式组织页面或连续章节：方法、框架、样本与排期采用适用的流程、矩阵、结构图或时间轴，标题不重复；内容可读、无裁切溢出，目录导航及所选翻页功能正常，离线可打开；与Markdown定稿的样本、日期、金额及方案一致。
- 项目用途与拟交付成果相符；混合模块共同回答客户问题，多方案的范围、样本、成果、日历与费用相互对应。

条件尚待确认时交付“讨论稿”，明确待定项；条件齐备并经相关方确认后可作为执行依据。

## 对客成文要求

计划书先交代委托方业务处境、目标与具体需求，再说明研究思路、方法和成果的用途。能力、经验及奖项页以真实材料说明对本项目的支持，不泛称专业优势。每页承担明确沟通任务，单页可读懂对象和价值；主标题说明对象，副标题以完整陈述讲清本页故事，正文充分展开。前后页逻辑相接，顺读副标题可理解整份方案。短语适合标签与表头，背景、判断和分析用完整句子；交付物与报价分别成页，资料提交归入协作安排。已有 `hehe-report-writing` 编辑成果可直接承接，不重复另写。
